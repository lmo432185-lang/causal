# 用户要求：转为小规模思路验证

2026-11-24，用户明确：“后面的实验，不需要跑很大的数据去验证，小数据的验证思路是否正确即可，继续做实验。”此要求优先于原全量补充计划。

- 保留已完成、已冻结的5000主模型、两批主预测与概率审计，不重训、不扩样。
- 收到要求时，主概率审计和短前缀测试A已接近完成，保留其完整输出；完成在途A后停止原短前缀全量B及其后续流水线。
- 未完成的全量B不使用；若进程刚创建文件，移入short/user_budget_stop并标为partial，不能当有效实验数据。它不是第二批完整短前缀复现。
- 只补6个事先固定代表条件A0、B1、C0、D0、E1、CE，种子4011–4013，各5条B轨迹，共90条。复用既有冻结1000前缀模型；同一B轨迹必须由原count20生成后取前5条，避免改count改变随机数路径。既有测试长度5000保持，仅用于与主结果配对，**不再新训练长轨迹模型**。
- 小样本用于验证计算链路与结果方向，不承担显著性、稳定性或5%误报率的最终证明。不能选择好看的条件重新测试，也不改变原5000主检验结论。
- 原主敏感性仅4条件×固定1种子，参数及哈希审计复用已有数据，不扩大实验。C5补表也缩到4条件×3种子×5条。

后续新实验默认先用2–3种关键系统、3种子、约20条训练、5条验证、10条测试、长度300–500的小原型；具体问题可进一步缩减。一次只验证一个核心假设。只有确需正式统计结论且用户另有要求时才扩大规模，不自动开展大批量网格。
